## Requisitos
1. Datas: Date/ISO/data simples/hora simples corretas no fuso local; rejeitar dias impossíveis na criação/reabertura. CSV BOM/separador corretos e neutralização de fórmulas em textos livres.
2. IndexedDB: escrita resolve em transaction.oncomplete, rejeita abort; primitive atomic multi-store documentada. Operações evento+histórico, duto+vínculos e importação são atômicas. Snapshot exportado consistente. Não alterar DB_NAME nem eliminar bases existentes.
3. Validação serviços: referências existem, são compatíveis (console→duto→vínculo UO→tipo→TAG), ativos para criação, manter inativos apenas na edição do próprio vínculo existente; UOs mínimas distintas; duplicidade case-insensitive bloqueada; alterações cadastrais não invalidam referências existentes. Datas/números/tipos/enum/cores/links validados.
4. Backup: validar TODAS as coleções/linhas/IDs/chaves/referências/datas/status/configurações/faixas, aceitar backups válidos produzidos pela versão antiga; nenhuma escrita se inválido. Missing coleções necessárias não pode significar apagar silenciosamente. Sanitizar/rejeitar IDs e stylusDrawing não PNG seguro para templates atuais. Validação de exportedAt obrigatória antes da UI. replace transação única com rollback. merge compara version e updatedAt, rejeita/relata conflitos sem perder dados, detecta duplicidades de negócio entre UUIDs diferentes; dois registros do mesmo ID no arquivo são inválidos. Documentar retorno de importJSON para UI comunicar contagem/conflitos.
5. Motor: usar ??/validação para zero, serializar tick e lock exclusivo entre abas (navigator.locks quando disponível + fallback localStorage lease); verificar estado atual transacional antes de disparo para não sobrescrever conclusão/reconhecimento concorrente; callbacks visuais via await/catch; título enquanto existe triggered; histórico registra canais realmente disponíveis e limite de repetição documentado. Reinício/reprogramação zera contador/ultimo disparo apropriadamente. Error logs alimentados sem loop infinito; version/updatedAt coerentes. Ponto público para UI atualizar canais/estado em tick sem renderizar páginas inteiras a cada segundo.
6. Registrar completedBy/createdBy reais, validação snooze1–1440, política não apagar histórico de forma silenciosa (tombstone inactive evento ou log de exclusão preservado), leitura filtrada não ressuscita eventos inativos. Demonstração é outra tarefa UI, mas loadDemoData e clearAllData precisam comportamento/documentação coerentes e atomicidade razoável.
